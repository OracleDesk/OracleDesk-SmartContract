## #292 — Separate Invalid threshold (ResolutionSpecV3 + InvalidPolicy)

**One-file edit:** `contracts/oracledesk-types/src/lib.rs`

Two new types appended after `ResolutionSpecV2`. Existing V1/V2 XDR is frozen and unchanged.

### New types

```rust
pub struct InvalidPolicy {
    pub threshold: u32,          // must be > Yes/No threshold AND <= member count
    pub allow_displacement: bool,
}

pub struct ResolutionSpecV3 {
    pub version: u32,            // must be 3
    pub network_id: BytesN<32>,
    pub market_core: Address,
    pub salt: BytesN<32>,
    pub rule: ResolutionSpec,
    pub invalid: Option<InvalidPolicy>,
}
```

### Commitment domain

`sha256("oracledesk:resolution-spec-v3" || XDR(ResolutionSpecV3))`

The `"…-v3"` suffix makes V3 preimages disjoint from V2 (`"oracledesk:resolution-spec"`) even when `invalid = None`.

### Displacement rules (resolver logic)

```
let may_propose = match load_proposal(env, market_id) {
    None => true,
    Some(p) if outcome == Invalid && p.outcome != Invalid => match policy {
        None    => true,   // V2 legacy: unrestricted
        Some(pol) => pol.allow_displacement
                  && !storage.has(DataKey::InvalidDisplaced(market_id)),
    },
    _ => false,
};
```

Set `DataKey::InvalidDisplaced` when displacement occurs (at most once per market).

### Edge cases

- `policy.threshold > member_count` → `InvalidConfig` error at reveal (market can never void).
- Committee rotation that shrinks membership below `policy.threshold` makes Invalid unreachable; do **not** lower `threshold` automatically.
- Hybrid: policy applies only after `open_fallback`; Price resolution ignores it.
- A signer may attest both Yes and Invalid (per-outcome dedup stays allowed).

## #291 — Atomic multi-leg trade entrypoint

**One-file edit:** `contracts/oracledesk-types/src/lib.rs` (also done in this PR — `LegKind`, `Leg`, `LegResult` appended)

### New types (already in `oracledesk-types`)

```rust
pub enum LegKind { BuyExactIn, SellExactOut }

pub struct Leg {
    pub market_id: u64,
    pub outcome: Outcome,
    pub kind: LegKind,
    pub amount: i128,         // collateral_in or collateral_out
    pub bound: i128,          // min_shares_out or max_shares_in
    pub limit_price_bps: u32, // 0 = no limit
}

pub struct LegResult { pub market_id: u64, pub collateral: i128, pub shares: i128 }
```

### Key invariants

- Duplicate `(market_id, outcome, kind)` → `Error::DuplicateLeg` (prevents `max_market` bypass).
- `net = Σ sell.collateral − Σ buy.collateral`; revert if `net < min_net`.
- Treasury: order sells before buys so proceeds can fund buys without extra liquidity.
- One `authorize_as_current_contract` call with one `token.transfer(treasury → market_core, amount_i)` entry **per buy leg** (entries matched by arguments; equal amounts still need two entries).
- `MAX_LEGS` chosen so the bundle stays under 80% of instruction / read / write / size limits.
